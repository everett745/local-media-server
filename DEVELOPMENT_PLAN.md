# План разработки (без сроков)

## Этап 0. Подготовка
- Зафиксировать scope Phase 1.
- Утвердить стек и структуру монорепо.
- Подготовить переменные окружения и базовый CI.

## Этап 1. Базовая платформа
- Поднять инфраструктуру: `web`, `api`, `worker`, `postgres`, `redis`.
- Настроить миграции БД.
- Реализовать auth (register/login/refresh/logout).

## Этап 1A. Docker-first разворачивание (обязательно)
- Подготовить Dockerfile для `web`, `api`, `worker`.
- Подготовить `docker-compose.yml` для полного app-стека.
- Подготовить отдельный `docker-compose.media.yml` для `jellyfin/jellyseerr/radarr/sonarr` (и `prowlarr` опционально).
- Настроить healthchecks и корректный startup order (`depends_on` + readiness).
- Обеспечить запуск проекта одной командой через Docker Compose.

## Этап 2. Каталог и карточки
- Реализовать сущность `titles`.
- Реализовать list/detail API.
- Добавить поиск/фильтры/пагинацию.
- Собрать базовые экраны каталога в web.

## Этап 3. Импорт по URL
- Добавить endpoint `import-by-url`.
- Реализовать parser-core (распознавание источника, извлечение ID).
- Запустить фоновые jobs на нормализацию и обновление метаданных.

## Этап 4. Preload интеграция
- Реализовать endpoint `POST /titles/:id/preload`.
- Интегрировать API с Jellyseerr.
- Добавить модель `preload_requests`.
- Добавить статусную модель `local_availability`.

## Этап 5. Синхронизация статусов
- Реализовать worker sync: Jellyseerr/Radarr/Sonarr -> локальные статусы.
- Поддержать статусы: `queued/downloading/available/failed`.
- Добавить retry/reconciliation.

## Этап 6. Web UX для preload
- Кнопка `Предзагрузить` на карточке.
- Экран/блок статусов запросов пользователя.
- Переход "Открыть в Jellyfin".

## Этап 7. Админ и эксплуатация
- Базовая админка управления тайтлами.
- Ручной перепарсинг и повтор sync.
- Логи, аудит, алерты.

## Этап 8. Качество и релиз
- Unit/integration/e2e тесты критических сценариев.
- Проверка отказоустойчивости очередей.
- Проверка полного контейнерного разворачивания в чистом окружении.
- Release checklist и запуск Phase 1.

## Этап 9. Phase 2 (optional)
- Принять решение: Yamtrack integration или собственный tracking модуль.
- Реализовать выбранный вариант без поломки Phase 1.

## Definition of Done для Phase 1
- Приложение поднимается только через Docker Compose без ручных шагов на хосте.
- App stack и media stack документированы и воспроизводимы.
- Критический пользовательский поток (поиск -> preload -> доступно в Jellyfin) проходит в контейнерной среде.
